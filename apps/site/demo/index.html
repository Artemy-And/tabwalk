Tabwalk presses Tab and Shift+Tab, tries Escape, and shows where keyboard navigation breaks. Start with this small example, then explore the report below.

The keyboard trap and its fix

Recording transcript: Tab enters the email field, then Subscribe. Tab cycles back to email. Shift+Tab and Escape cannot leave the form. After removing the custom focus loop, Tab reaches the privacy link and Shift+Tab leaves the form.

Same markup. Different keyboard behaviour.

Static checks alone miss this trap.

Counts above come from scanning both versions with the same Tabwalk checkers. Zero findings does not establish accessibility.

See the fix

Remove the custom Tab handler from this ordinary form. Native keyboard navigation already moves between its controls and the rest of the page.

// Remove the handler that redirects focus:
if (!event.shiftKey && active === last) {
  event.preventDefault();
  first.focus();
}

Run the same example yourself.

This is a read-only snapshot, generated from the examples in the repository. Filters and print work here; scheduling, notifications and new scans run in your own installation.

git clone https://github.com/Artemy-And/tabwalk.git
cd tabwalk
docker compose -f docker-compose.yml \
  -f docker-compose.demo.yml up -d

Open http://localhost:8080, create your local admin account, add http://acmestore.example/ and run a scan.
